== Requirements

The Python SDK requires CPython {python-min-version} or later.
See the xref:project-docs:compatibility.adoc#python-version-compat[Python Version Compatibility] section for details on supported versions of Python.

=== Binary Wheels

Most installs need nothing beyond a supported Python and `pip`.
PyPI carries one stable-ABI (`abi3`) wheel per platform, and that one wheel works on every supported Python version from {python-min-version} up.
`pip` selects it automatically.
The wheel bundles the {cpp} core, Couchbase{plus}{plus}, and statically links BoringSSL, so there is no compiler, CMake or SSL library to install.

=== Building from Source

When no wheel matches the platform, `pip` builds the SDK from its source distribution.
That build needs:

* A {cpp} 17 compiler, such as GCC 8 or later.
* CMake 3.19 or later. If CMake is not found, the installer downloads it from PyPI.
* The OpenSSL headers and libraries, since a source build links against the system OpenSSL by default.
* A `pip` recent enough to support PEP 517. If the build fails early, upgrade `pip`, `setuptools` and `wheel` first:
+
[source,console]
----
$ python3 -m pip install --upgrade pip setuptools wheel
----

The https://github.com/couchbase/couchbase-python-client/blob/master/BUILDING.md[build instructions^] on GitHub cover the build options, including linking BoringSSL instead of OpenSSL.

=== Dependencies

`pip` installs these alongside the SDK:

* `typing-extensions`, on Python versions before 3.13.
* `grpcio`, `protobuf`, `googleapis-common-protos` and `certifi`, which `couchbase2://` connections use.

The optional `otel` extra adds the OpenTelemetry API and SDK, as described in xref:howtos:observability-metrics.adoc[]:

[source,console]
----
$ python3 -m pip install "couchbase[otel]"
----

// end::prep[]

=== PyPy support

Because the Python SDK is written primarily in C using the CPython API, the official SDK will not work on PyPy.


== Installation

For xref:compatibility.adoc#platform-compatibility[supported Operating Systems]:

[{tabs}] 
====
macOS::
+
--
The steps below install Python with _Homebrew_ and the SDK into a virtual environment. To manage several versions of Python, use _pyenv_ instead of `brew`.

The Python SDK has a wheel for macOS covering xref:compatibility.adoc#python-version-compat[supported versions of Python].

NOTE: The Python that ships with Xcode is often older than {python-min-version}.
Install a supported Python via https://github.com/pyenv/pyenv#homebrew-on-macos[pyenv^]
(see the Python SDK https://github.com/couchbase/couchbase-python-client#macos-pyenv[Github README^] for further details on pyenv installation), http://brew.sh/[Homebrew^], or https://www.python.org/downloads[python.org^].

To install the library on Mac OS, first install http://brew.sh/[Homebrew^]. 

NOTE: Later versions of Mac OS can break the python3 homebrew installer. 
Simple mitigating steps may be found https://stackoverflow.com/questions/47255517/brew-install-python3-didnt-install-pip3[here^].

The following example uses the Python supplied by the _Homebrew_ package manager and not the vendor-supplied Python which ships with Mac OS. Once _Homebrew_ is configured:

.Get a list of the latest packages
[source,console]
----
$ brew update
----

.Install compatible Python 3
[source,console]
----
$ brew install python3
----

.For ZSH (MacOS 10.15 Catalina and newer)
[source,console]
----
$ echo 'export PATH="/usr/local/bin:"$PATH' >> ~/.zshrc
----

[source,console]
----
$ source ~/.zshrc
----

Create a virtual environment, activate it, and install the latest Python SDK:

[source,console]
----
$ python3 -m venv .venv
$ source .venv/bin/activate
$ python -m pip install couchbase
----

--

Debian & Ubuntu::
+
--
This SDK runs on top of the {cpp} core, Couchbase{plus}{plus}, which requires a {cpp} 17 compiler, such as GCC 8.0, or more recent versions, when building from source. Older versions of Debian and Ubuntu ship with an older version of GCC.

IMPORTANT:  While workarounds are available for installing a newer build chain, some may not be within your company’s policy, so also take a look at container options -- such as the unofficial Docker builds provided in the Python SDK 4.x examples folder https://github.com/couchbase/couchbase-python-client/tree/master/examples/dockerfiles[here^], which can at least be used as a reference to a known working set-up.

Check that you have a new enough release of Python.

Best practice is to use a Python virtual environment such as _venv_ or _pyenv_ to manage multiple versions of Python. 
See https://github.com/pyenv/pyenv#basic-github-checkout[pyenv docs^] for details.

The Python SDK has a manylinux wheel covering xref:compatibility.adoc#python-version-compat[supported versions of Python].

During first-time setup:

[source,console]
----
$ sudo apt-get install git-all python3-dev python3-pip python3-venv python3-setuptools build-essential
----

First, make sure the <<requirements,requirements>> have been installed.

Create a virtual environment, activate it, and install the latest Python SDK:

[source,console]
----
$ python3 -m venv .venv
$ source .venv/bin/activate
$ python -m pip install couchbase
----
--

RHEL & CentOS::
+
--
This SDK runs on top of the {cpp} core, Couchbase{plus}{plus}, which requires a {cpp} 17 compiler, such as GCC 8.0, or more recent versions, when building from source. Older versions of RHEL and CentOS ship with an older version of GCC.

IMPORTANT:  Workarounds are available for installing a newer build chain with https://fedoraproject.org/wiki/EPEL[EPEL^], but this may not be within your company’s policy, so also take a look at container options -- such as the unofficial Docker builds provided in the Python SDK 4.x examples folder https://github.com/couchbase/couchbase-python-client/tree/master/examples/dockerfiles[here^], which can at least be used as a reference to a known working set-up.

Check that you have a new enough release of Python, and if not then investigate the https://fedoraproject.org/wiki/EPEL[EPEL^] repository.

Best practice is to use a Python virtual environment such as _venv_ or _pyenv_ to manage multiple versions of Python. 
See https://github.com/pyenv/pyenv#basic-github-checkout[pyenv docs^] for details.

The Python SDK has a manylinux wheel covering xref:compatibility.adoc#python-version-compat[supported versions of Python].

During first-time setup:

[source,console]
----
$ sudo yum install gcc gcc-c++ python3-devel python3-pip
----

TIP: You may need to update your installed version of CMake.
For example, by following the steps https://idroot.us/install-cmake-centos-8[here^].


NOTE: RHEL/CentOS distributions may not provide the `python3-pip` package in the base repositories.
It may be found in the https://fedoraproject.org/wiki/EPEL[EPEL^] repository.

First, make sure the <<requirements,requirements>> have been installed.

Create a virtual environment, activate it, and install the latest Python SDK:

[source,console]
----
$ python3 -m venv .venv
$ source .venv/bin/activate
$ python -m pip install couchbase
----
--

Windows::
+
--
Download and install Python from https://www.python.org/downloads[python.org^].  
Best practice is to use a Python virtual environment such as _venv_ or _pyenv_.

TIP: Checkout the https://github.com/pyenv-win/pyenv-win[pyenv-win^] project to manage multiple versions of Python.

The Python SDK has a wheel for Windows covering xref:compatibility.adoc#python-version-compat[supported versions of Python].

First, make sure the <<requirements,requirements>> have been installed.

Create a virtual environment, activate it, and install the latest Python SDK:

[source,console]
----
python -m venv .venv
.venv\Scripts\activate
python -m pip install couchbase
----

The Windows wheel statically links BoringSSL, so it does not depend on the OpenSSL DLLs that ship with Python.

NOTE: If you require a version that doesn't have a suitable binary wheel on PyPI, follow the https://github.com/couchbase/couchbase-python-client#install-windows-alt[build instructions^] on the GitHub repo.
--

Conda::
+
--
To use the SDK within the Anaconda / Miniconda platform, make sure the prerequisites for the desired Operating System are met:

`git-all python3-dev python3-pip python3-setuptools build-essential`

In the _Anaconda Prompt_, create a new environment:
[source,console]
----
conda create -n test_env python=3.12
----

Activate the environment:
[source,console]
----
conda activate test_env
----

Install the SDK:
[source,console]
----
python -m pip install couchbase
----

NOTE: If you require a version that doesn't have a suitable binary wheel on PyPI, follow the https://github.com/couchbase/couchbase-python-client#install-anaconda[build instructions^] on the GitHub repo.
--

=== Installing a Specific Version

You may install previous versions of the SDK using pip.

[source,console]
----
$ python3 -m pip install couchbase==VERSION
----

Where VERSION is the version you wish to install. 
For example, to install version {sdk_current_version}:

[source,console,subs="attributes+"]
----
$ python3 -m pip install couchbase=={sdk_current_version}
----

For more detailed installation instructions, see the xref:project-docs:sdk-full-installation.adoc[full installation guide].
